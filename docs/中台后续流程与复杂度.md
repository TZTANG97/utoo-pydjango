# 中台后续流程与代码复杂度

> 约定文档已齐（见 [README.md](./README.md)），`X-Channel` 已在管理端 / C 端 / 网关透传。  
> **后续不是另起项目**，而是按域把业务真正「只留一份」并强制走 `SVC_*`。

## 1. 整体流程（按顺序）

```text
已完成文档约定
    → 订单域试点（开 SVC_ORDER_URL）
    → 支付域收口
    → 资产域收口
    → 平台域收口
    → 对内中台验收
```

| 步骤 | 做什么 | 动作 | 文档 |
|------|--------|------|------|
| 0（已完成） | 能力归属、身份菜单、twin 清点、表写归属 | [`docs/中台*.md`](./README.md) | — |
| 1 | **订单域试点** | 开 `SVC_ORDER_URL`；两端订单主路径只打 order；冻结 twin 新业务 | [中台订单域试点.md](./中台订单域试点.md) |
| 2 | **支付域收口** | 开 `SVC_PAYMENT_URL` | [中台域收口方法.md](./中台域收口方法.md) |
| 3 | **资产域收口** | 开 `SVC_ADMIN_ASSET_URL` | 同上 |
| 4 | **平台域收口** | 开 `SVC_ADMIN_PLATFORM_URL`（入驻/发票 → 18091） | 同上 |
| 5 | **全程纪律** | 新功能只写 `qd_svc_*`；前端不拼状态机；表变更注明写服务 | [中台网关下沉与转发.md](./中台网关下沉与转发.md)、[中台数据与发版治理.md](./中台数据与发版治理.md) |
| 6 | **验收** | 核心域生产走 svc；两端无重复业务实现 | 见下文 §4 |

后台页面迁移（`qd_admin_front`）**可继续**，但每页只调已归属服务的 ajax，不在网关再堆业务。

## 2. 每一域内部小循环

1. 对照 [中台能力清单.md](./中台能力清单.md) 锁定路径前缀  
2. 核对网关 twin 与 `qd_svc_*` 是否齐  
3. 环境打开对应 `SVC_*_URL`  
4. 跑通管理端 + C 端（或仅管理端）主路径  
5. 新改动只进 svc；网关 twin 标注勿增业务  

## 3. 代码改起来复不复杂？

**总评：中等偏纪律，不是架构推倒重来。** 底座（网关转发、域服务、共用库）已有；难在「别再写第二份」和按域回归。

| 改动类型 | 复杂度 | 说明 |
|----------|--------|------|
| 开 `SVC_*_URL`、启对应进程 | **低** | 配置 + [`scripts/start-*.ps1`](../scripts/) |
| 网关补 `@forward_*_first` / 前缀代理 | **低～中** | 多数域已有；缺哪条补哪条 |
| 新功能写进正确 `qd_svc_*` | **低**（有纪律时） | 比「随便写网关」多选一下目录 |
| 两端页面改调同一套 API | **中** | 多数已走 `/api/...`；删前端拼规则 |
| twin 与 svc **行为不一致**时对齐 | **中～高** | 订单/支付状态机最易踩坑 |
| 拆库 / 禁止跨域 SQL | **高（中后期）** | 短期共用 `qd_pt_new`，先守唯一写服务 |
| 多租户 / 工厂大平台产品化 | **不在本阶段** | 当前只做对内中台 |

### 一般不用大改

- 前端工程拆分、换技术栈  
- 再造登录（后台登录仍在网关 `admin_auth`）  
- 为中台重写所有页面  

### 真正费时间

- 订单试点回归（创建 / 审核 / 取消 / 子单，两端一致）  
- twin 与 svc 分叉后的合并  
- 团队习惯：新 PR 只进 svc  

## 4. 对内中台验收标准

- [ ] 能力清单与代码归属一致  
- [ ] 登录 / 菜单约定被遵守（无第二套权限树）  
- [ ] 核心域（至少订单 + 支付 + C 端登录）生产走 `SVC_*` 转发  
- [ ] 管理端与 C 端无重复业务实现  
- [ ] 新需求默认进中台 API，不开平行逻辑  

## 5. 建议立刻做的下一件事

1. 联调打开订单转发，按 [中台订单域试点.md](./中台订单域试点.md) §「执行清单」跑验收。  
2. 通过后再：支付 → 资产 → 平台。  
3. 每个需求先查能力清单选服务。

**一句话**：流程是「文档已齐 → 按域开转发 → 只留 svc 一份逻辑 → 验收」；代码以**配置、转发补齐、行为对齐**为主，**不复杂到重写**，但订单/支付收口要认真回归。
