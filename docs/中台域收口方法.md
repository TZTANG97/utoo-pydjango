# 中台域收口方法（支付 → 资产 → 平台）

订单试点完成后，按同一方法复制到其余域。每域一轮，不要并行摊薄。

## 标准循环（每个域）

1. **划界**：对照 [中台能力清单.md](./中台能力清单.md) 锁定路径前缀与负责服务。  
2. **清单**：列出管理端 / C 端实际调用的 ajax，与 svc URL 对齐。  
3. **开转发**：预发配置对应 `SVC_*_URL`，跑通主路径。  
4. **删重复**：禁止只改网关 twin；新逻辑只进 svc。  
5. **验收**：两端（或仅管理端）主流程 + 回退说明。  
6. **冻结 twin**：网关同名模块仅保留兼容，标注「勿增业务」。

---

## A. 支付域 → `qd_svc_payment`（18084）

| 项 | 内容 |
|----|------|
| 变量 | `SVC_PAYMENT_URL` |
| 路径 | `/api/paymentapply/*`、`/api/offlineRecharge/*`、支付相关 `/api/pc/*`、`/api/redeem/*`（支付侧） |
| 端 | 管理后台支付申请/记录；C 端支付与充值 |
| 网关 twin | `apps/payments`、`pc_compat` 支付视图 |
| 验收最低集 | 发起支付申请、回调/状态查询、线下充值审核、与订单关联字段一致 |

**注意**：订单状态仍由 `qd_svc_order` 负责；支付服务通过订单号关联，不复制订单状态机。

---

## B. 资产域 → `qd_svc_admin_asset`（18090）

| 项 | 内容 |
|----|------|
| 变量 | `SVC_ADMIN_ASSET_URL` |
| 路径 | `/api/digital/*`、`/api/inventory/*`、`/api/storeHouse/*`、`/api/lab/*`、`/api/funds/*`、各类 `*Pay*`、`inIncome` 等 |
| 端 | **主要为管理后台**（数字化 / 库存 / 资金） |
| 网关 twin | `admin_digital`、`admin_inventory`、`admin_fund` |
| 验收最低集 | 库存列表与写操作、资金账户流水、数字化报表关键查询 |

**注意**：资产写库存表时遵守 [中台数据与发版治理.md](./中台数据与发版治理.md) 的唯一写服务规则。

---

## C. 平台域 → `qd_svc_admin_platform`（18091）

| 项 | 内容 |
|----|------|
| 变量 | `SVC_ADMIN_PLATFORM_URL`（入驻/发票另配 `SVC_ENTRY_URL` / `SVC_INVOICE_URL` → 同主机） |
| 路径 | `/api/sys/*`、`/api/member/*`、`/api/banner/*`、`/api/goods*`、`/api/apply/*`、`/api/edit/*`、`/api/entry/*`、`/api/invoice/*`、订单设置等 |
| 端 | 管理后台为主；C 端读配置 / 入驻 / 发票 |
| 网关 twin | `admin_system`、`admin_member`、`admin_ops`、`admin_service`、`admin_settings`、`entry`、`invoices` |
| 验收最低集 | 菜单用户角色、一处运营配置读写、发票申请、入驻审核 |

**注意**：后台员工登录仍留网关 `admin_auth`，不迁入 platform。

## 管理面 vs 消费面（穿插执行）

| 面 | 工程 | 职责 |
|----|------|------|
| 管理面 | `qd_admin_front` | 配置、审核、主数据、运营 |
| 消费面 | `qd_test_front_v3`（及微信） | 下单、支付、查询 |

两边 UI 可不同；**禁止各写一套后端流程**。产品验收话术：「这个按钮打的是哪个中台 API？」——须能对应到能力清单中的一行。
