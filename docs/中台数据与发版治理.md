# 中台数据与发版治理

## 1. 短期：共用库 + 唯一写服务

迁移期继续共用 MySQL **`qd_pt_new`**（见 `config/shared-database.env`）。

**铁律**：每张核心业务表只允许 **一个** `qd_svc_*`（或网关永久模块）作为写入口；其他服务只读或经 HTTP 调写方。

### 核心表归属（初版，按域约定）

| 表/表族（示意） | 唯一写服务 | 说明 |
|-----------------|------------|------|
| 订单 / 子单 / 复测 / 订单日志 | `qd_svc_order` | 含 `adminExperiment` 写路径 |
| 支付申请 / 充值单 / 支付回调落库 | `qd_svc_payment` | 不写订单状态机 |
| 库存 / 仓库 / 实验室相关 | `qd_svc_admin_asset` | |
| 资金账户 / 资金流水 | `qd_svc_admin_asset` | |
| 会员 / 积分账 / VIP 申请 | `qd_svc_admin_platform` | |
| 系统用户/角色/菜单/部门/公司 | `qd_svc_admin_platform` | 后台员工登录态签发仍在网关 `admin_auth`，用户主数据写归 platform |
| 运营配置 / 广告 / 商品运营 / 相册 | `qd_svc_admin_platform` | |
| 入驻 / 发票 | `qd_svc_admin_platform` | |
| C 端账号认证扩展（若独立表） | 网关 `auth_pc` | 与会员主数据边界在变更时评审 |
| `accessory` 等附件 | 按业务外键归属写方 | 订单附件随订单域；相册图随 platform |

变更表结构：PR 必须注明 **写服务**；跨域加字段走评审。

### 读模型

允许他域 **只读** 查询（过渡期），但：

- 禁止跨服务事务直接改他域表；  
- 中期改为 API / 事件同步，减少跨域 SQL。

## 2. 中期：拆库或拆 schema

当域边界稳定后：

1. 按服务拆 schema 或独立库；  
2. 跨域只走 HTTP 或 Celery（`qd_worker`）；  
3. 网关不再持有 twin 写逻辑。

## 3. 发版兼容

沿用 [`deploy/README.md`](../deploy/README.md)：网关与各 `qd_svc_*`、前端可独立发版。

| 规则 | 说明 |
|------|------|
| 向后兼容 | 中台 API **至少** 向后兼容一个小版本（路径与主字段不随意删） |
| 破坏性变更 | 先双写或新路径，再下线旧路径；公告窗口 ≥ 一个发版周期 |
| 端与中台 | 前端发版不强制捆绑全部 svc；但依赖的 API 须已在目标环境发布 |
| 数据库 | 先扩容兼容（加列可空/默认），再发读新列的服务，最后再收紧约束 |
| 回滚 | svc 可单独回滚；避免「仅回滚前端、库已破坏性变更」 |

### 建议发版顺序（有库变更时）

```text
1) DB 兼容迁移 → 2) 写服务 → 3) 读服务/网关 → 4) 前端
```

## 4. 完成标准

- 核心表有书面写归属，PR 可检查。  
- 改订单服务不必发支付服务（无交叉写时）。  
- 预发/生产发版记录能对应到服务版本与兼容说明。
