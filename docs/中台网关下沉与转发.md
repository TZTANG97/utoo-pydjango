# 中台网关下沉与转发

## 目标态

```text
Browser → 前端 → Gateway:18083 →（配置 SVC_*_URL）→ qd_svc_* 
                              ↘（未配置时）网关进程内 twin 回退
```

- **日常开发**：可不配 `SVC_*_URL`，业务在网关 in-process（联调方便）。  
- **预发/生产（中台成型）**：核心域 **必须** 配置对应 `SVC_*_URL`，业务逻辑以 svc 为准。  
- **新功能**：只写在负责 `qd_svc_*`；网关最多加 URL include + `@forward_*_first`。

| 网关 app | 目标服务 | 下沉状态 | 说明 |

| `admin_auth` | — | **永久驻留网关** | 后台登录、`/api/vue/*` 壳 |

## 下沉检查清单（每个域上线前）

1. [ ] 对应 `qd_svc_*` 已包含与网关 twin **同等** 的 URL 与行为。  
2. [ ] 网关视图已挂 `@forward_*_first` 或 urls 前缀代理。  
3. [ ] 预发配置该 `SVC_*_URL`，跑通管理端 + C 端关键路径。  
4. [ ] 文档标注：生产以 svc 为准；网关代码仅兼容回退（计划删除前勿再改 twin 业务）。  
5. [ ] **禁止** 新需求只改网关 twin、不改 svc。

## 仍须留在网关的能力

- 后台员工登录与 Vue 壳（`admin_auth`）  
- C 端认证（`auth_pc`）  
- 未归属微服务的兼容入口（应逐步清空）  
- 转发层本身（`svc_proxy` / `*_forward`）

## 完成标准

生产/预发开齐核心 `SVC_*_URL` 后，订单 / 支付 / 认证 / 资产 / 平台主链路 **不依赖** 网关内业务实现即可运行。
