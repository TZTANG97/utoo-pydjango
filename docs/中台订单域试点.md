# 中台订单域试点

> 目标：管理后台与 C 端对「实验订单」状态变更只调 **`qd_svc_order`**（经网关转发），改规则只改一处。

## 1. 范围

| 场景 | 端 | 路径族 | 服务 |
|------|----|--------|------|
| 下单 / 我的订单 / 详情 / 取消等 | C 端 | `/api/experimentOrder/*`、订单相关 `/api/pc/*.ajax` | `qd_svc_order` |
| 子单 / 样品 | 两端 | `/api/experimentChildOrder/*`、`/api/ordersampleinfomation/*` | `qd_svc_order` |
| 复测 | 两端 | `/api/retestapplication/*` | `qd_svc_order` |
| 后台订单列表 / 审核 / 结算 / 导出 | 管理后台 | `/api/adminExperiment/order/*` | `qd_svc_order` |
| 实验主数据（类目/品牌/项目/商品） | 管理后台 | `/api/adminExperiment/{manage,brand,project,goods,sampleAttr}/*` | `qd_svc_order` |
| 业务咨询 | 两端 | `/api/consult/*` | `qd_svc_order` |

前端入口示例：

- 管理端：`qd_admin_front/src/api/experiment.ts`、`service-platform.ts`（评价列表等）  
- C 端：`qd_test_front_v3/src/api/order.js`

## 2. 试点收口循环（必须按序）

```text
梳理接口清单 → 对照 svc 与网关 twin → 预发开 SVC_ORDER_URL
→ 两端只打上述路径 → 回归状态机 → 冻结网关 twin 业务改动
```

### 2.1 梳理接口

在 `qd_svc_order` 与网关 `apps/orders`、`apps/admin_experiment`、`pc_compat` 订单相关视图中列出：

- 方法 / 路径  
- 写哪些表  
- 是否改变订单状态  

产出可附本文件附录或单独表格。

### 2.2 统一行为

同一业务动作（如「审核通过」「取消订单」）若管理端与 C 端路径不同，**服务层须共用同一 service/repository 函数**，禁止两套状态机。

### 2.3 联调开关

```env
# 网关 .env
SVC_ORDER_URL=http://127.0.0.1:18082
```

启动：`qd_svc_order`（18082）+ 网关（18083）。

### 2.4 验收用例（最低集）

| # | 用例 | 期望 |
|---|------|------|
| 1 | C 端创建订单 | 落库成功，状态符合现网 |
| 2 | 管理端列表可见该单 | 同一 `order_id` |
| 3 | 管理端审核/取消 | 状态变更；C 端详情一致 |
| 4 | 子单关键写操作 | 仅 order 服务写订单相关表 |
| 5 | 关闭 `SVC_ORDER_URL` 回退 | 行为一致（过渡期）；长期以开转发为准 |

## 3. 纪律

- 新订单功能：**只改 `qd_svc_order`**，再视需要在网关加转发。  
- 管理端页面禁止在前端拼订单状态机；只调 ajax。  
- 支付、开票不进本试点范围（见支付/平台域收口）。

## 4. 完成标准

- 预发 `SVC_ORDER_URL` 常开。  
- 管理端 + C 端订单主路径无第二套后端实现。  
- 状态变更文档化，且代码中可指向同一 service 入口。

## 5. 执行清单（联调可勾选）

### 5.1 启动

```powershell
# 终端 1：订单服务
.\scripts\start-order.ps1

# 终端 2：网关（须已配置 SVC_ORDER_URL，见下方）
.\scripts\start-gateway.ps1

# 或一键订单试点（网关 + order）
.\scripts\start-order-pilot.ps1
```

网关 `qd_test_server_django/.env` 或 `.env.local` 至少包含：

```env
SVC_ORDER_URL=http://127.0.0.1:18082
```

仅测订单时可暂不启其它 svc；未配置的域仍走网关本地 twin。若已配置其它 `SVC_*_URL` 但未启对应进程，那些域会 503。

### 5.2 验收勾选

- [ ] C 端创建订单成功，状态符合现网  
- [ ] 管理端订单列表可见同一 `order_id`  
- [ ] 管理端审核或取消后，C 端详情状态一致  
- [ ] 子单关键写操作无报错，数据落在订单相关表  
- [ ] （过渡）清空 `SVC_ORDER_URL` 回退网关 twin，主路径仍可用；**预发/生产以开启转发为准**  
- [ ] 本轮起：订单相关 PR **只改** `qd_svc_order`（网关仅补转发时例外）

### 5.3 发现问题怎么处理

| 现象 | 处理 |
|------|------|
| 开转发后 502/503 | 确认 `qd_svc_order` 已起在 18082；看网关日志 |
| 开转发与关转发行为不一致 | 以 svc 为准对齐 twin，或把缺失逻辑补进 `qd_svc_order` |
| 仅管理端或仅 C 端失败 | 查该端调用的路径是否已挂 `@forward_order_first` / 前缀代理 |

整体推进顺序与复杂度说明见 [中台后续流程与复杂度.md](./中台后续流程与复杂度.md)。
