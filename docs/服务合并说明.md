# 服务合并说明（2026）

## 1. 网关 + 认证 → 网关一进程

| 原服务 | 现归属 |
|--------|--------|
| `qd_test_server_django` :18083 | 不变，增加「永久」承担 C 端认证 |
| `qd_svc_auth` :18081 | **废弃** |

- 后台登录：`admin_auth`（本来就在网关）
- C 端 `/api/auth/*`：网关 `apps/auth_pc`（**清空 `SVC_AUTH_URL`**）
- 勿再启动 `qd_svc_auth` / `scripts/start-auth.ps1`（脚本会提示废弃）

## 2. 支付 + 微信 → `qd_svc_payment` 一进程

| 原服务 | 现归属 |
|--------|--------|
| `qd_svc_payment` :18084 | 支付/资产 + 扫码/预约/反馈 4 个 `/api/wx` |
| `qd_svc_wx` :18087 | **废弃** |

- 代码：`qd_svc_payment/apps/wx/`（自原 wx 服务复制）
- 网关：`SVC_PAYMENT_URL` 与 `SVC_WX_URL` **均指向** `http://127.0.0.1:18084`；`SVC_WX_URL` **仅**转发上述 4 接口
- 小程序其余 `/api/wx/*`（登录等）在网关 `apps/wx_mp`，见 [小程序对接Django.md](./小程序对接Django.md)
- 扫码登录环境变量：`WEIXIN_GZH_APPID` / `WEIXIN_GZH_SECRET`（写在 payment 的 `.env` 或 shared）
- `scripts/start-wx.ps1` 会转启 payment

## 3. 本地联调清单

```powershell
# 网关 .env：勿设 SVC_AUTH_URL；SVC_WX_URL=http://127.0.0.1:18084
.\scripts\start-ms-dev.ps1
```

验证：

- C 端登录：网关处理（不依赖 18081）
- `/api/wx/WeChatQRCodeGenerator.ajax`：转发到 18084
- 支付相关：仍 18084

## 4. 服务器

停用 systemd：`qd-auth`、`qd-wx`；更新网关 `.env` 后重启网关与 `qd-payment`。详见 [deploy/README.md](../deploy/README.md)。
